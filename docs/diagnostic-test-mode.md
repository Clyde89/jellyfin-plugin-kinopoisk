# Диагностический тестовый режим КиноПоиска

## Назначение

Режим предназначен для контролируемого сбора событий КиноПоиска без изменения глобального уровня журналирования Jellyfin.

Диагностика записывается независимым прямым каналом событий плагина в отдельный JSONL-файл. Канал не зависит от runtime-регистрации `ILoggerProvider` и `ILoggerFactory` Jellyfin.

## Запуск

1. Открыта единая страница параметров плагина.
2. Выбрана вкладка `Диагностика (Debug)`.
3. Установлены требуемые уровень, продолжительность, размер файла и количество сохраняемых файлов.
4. Нажата кнопка `Начать новую сессию`.

При запуске новой сессии стартовый JSONL создаётся сразу, до выполнения API-запроса или обновления метаданных.

## Уровни

- `Базовый` — сохранены информационные события, предупреждения и ошибки.
- `Подробный` — дополнительно сохранены диагностические события API и операций поставщика.
- `Трассировка` — дополнительно сохранены события оперативного, дискового и файлового кэшей.

## Ограничения

- Продолжительность сессии ограничена конфигурацией и автоматически завершается.
- Размер текущего JSONL ограничен; при достижении предела выполнена ротация.
- Количество сохраняемых файлов ограничено параметром удержания.
- Write-режим франшиз не включается диагностической сессией.
- Preview не запускается автоматически.
- Apply-задача не создаётся и не запускается диагностическим режимом.

## Безопасность

API-токен и заголовки авторизации не записаны в диагностический JSONL.

Перед записью выполнены:

- полное маскирование значения заголовка `Authorization`;
- маскирование `X-Api-Key`, `ApiToken` и именованных токенов;
- удаление query-параметров и fragment из URL;
- ограничение длины строковых полей;
- изоляция ошибок файловой записи от основного поставщика метаданных.

## Наблюдаемость

Прямой файловый канал ведёт внутреннее состояние:

- факт подключения канала;
- количество полученных событий;
- количество успешно записанных событий;
- количество ошибок записи;
- время последней успешной записи;
- абсолютный путь текущего файла;
- имя последнего события;
- последняя ошибка записи.

Счётчики API и кэшей формируют структурированные события непосредственно через `KinopoiskDiagnostics`, поэтому диагностический JSONL не зависит от фильтров основного журнала Jellyfin.

## Путь

Файл создаётся в каталоге данных плагина:

```text
<Plugin.DataFolderPath>/diagnostics/kinopoisk-diagnostic-<session-id>.jsonl
```

Для стандартной Docker-конфигурации Jellyfin путь внутри контейнера имеет вид:

```text
/config/plugins/Jellyfin.Plugin.Kinopoisk/diagnostics/kinopoisk-diagnostic-<session-id>.jsonl
```

## Порядок runtime-проверки

1. Запущена новая короткая сессия с уровнем `Трассировка`.
2. До выполнения API-запроса подтверждено создание стартового JSONL.
3. Выполнен один безопасный поиск через `Распознать` без выбора результата и сохранения.
4. Подтверждено увеличение размера файла и появление событий `api.request` или кэша.
5. Проверены корректность JSONL и отсутствие открытых секретов.
6. Сессия остановлена после завершения проверки.

Массовое обновление библиотеки, Preview и Apply в runtime-проверку не входят.
