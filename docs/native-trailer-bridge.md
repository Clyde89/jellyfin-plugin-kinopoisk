# NativeTrailerBridge 10.11.0.11

`NativeTrailerBridge` использует штатный механизм Jellyfin `LocalTrailer`, поэтому нативные клиенты запускают трейлер внутренним плеером без изменения Android TV-приложения и без внешнего браузера.

## Рабочая схема

1. Авторизованный клиент открывает карточку фильма через стандартный маршрут Jellyfin.
2. Плагин проверяет тип `Movie`, положительный `ProviderIds.kinopoisk` и наличие HTTPS-виджета КиноПоиска в `RemoteTrailers`.
3. LocalTrailer регистрируется в базе Jellyfin без сетевого ожидания, а подготовка MP4 запускается в фоне.
4. HLS КиноПоиска сохраняется в MP4 с `-codec copy`: H.264 и AAC не перекодируются.
5. При первом немедленном запуске PlaybackInfo ждёт фоновую операцию не дольше настроенного интервала. Готовый файл выдаётся как локальный Direct Play.
6. При тайм-ауте или временной ошибке остаётся проверенный серверный HLS-резерв r7 с обязательными `Referer` и `Origin`.

Параллельные запросы одного фильма объединяются. Дубликаты фильма с одним Kinopoisk ID используют один файл кэша, но получают отдельные устойчивые LocalTrailer ID.

## Настройки

- `EnableNativeTrailerCache` — общий выключатель кэша и автоматической регистрации;
- `NativeTrailerCacheClientScope` — `AllClients` либо `AndroidTvOnly`;
- `NativeTrailerCachePopulationMode` — `OnDemand` либо `DuringMetadataScan`;
- `NativeTrailerCachePlaybackWaitSeconds` — ожидание MP4 при первом запуске, 0–60 секунд;
- максимальный общий размер — 256–16384 МБ, по умолчанию 4096 МБ;
- максимальный размер одного файла — 64–2048 МБ;
- срок неиспользования — 7–365 дней, по умолчанию 30 дней.

`OnDemand` — рекомендуемый режим: место расходуется только после открытия карточки. `DuringMetadataScan` начинает подготовку после успешного получения метаданных фильма, но карточка всё равно остаётся безопасным резервным триггером.

Плановая очистка выполняется по воскресеньям в 04:15. При превышении лимита сначала удаляются давно не использовавшиеся файлы. Временные недописанные файлы создаются атомарно и удаляются после ошибки либо плановой очисткой.

## Статистика кэша

Страница параметров показывает фактический размер каталога и количество MP4, число попаданий и промахов при запросах `PlaybackInfo`, долю попаданий, успешные и неуспешные записи, удаление по LRU и число активных фоновых подготовок. Внутренние проверки карточки не увеличивают счётчики попаданий и промахов.

Размер и количество файлов читаются с диска. Оперативные счётчики хранятся в памяти и начинают новый интервал после перезапуска Jellyfin; начало интервала показано полем «Статистика с».

## Веб- и мобильный клиенты

При `AllClients` Runtime Web Bootstrap передаёт кнопку трейлера штатному плееру Jellyfin, если сервер уже зарегистрировал `LocalTrailer`. Это распространяет единый кэш на браузер и основанные на Web UI мобильные клиенты. Клиенты, которые сами вызывают `/Items/{itemId}/LocalTrailers`, используют тот же серверный объект без клиентского расширения.

При `AndroidTvOnly` автоматический триггер принимает только авторизованные запросы с клиентом `Jellyfin Android TV`. Уже зарегистрированный LocalTrailer является глобальным объектом медиатеки и может оставаться видимым другим клиентам.

Jellyfin Web и основанные на Web UI мобильные клиенты запрашивают безопасное состояние подготовки. Если MP4 ещё создаётся, перед передачей кнопки штатному плееру показывается уведомление «Трейлер подготавливается на сервере». Нативный Android TV не исполняет Runtime Web Bootstrap, поэтому без изменения приложения использует собственный стандартный индикатор загрузки.

## YouTube fallback и сетевой маршрут

Порядок источников остаётся `КиноПоиск → YouTube`. Если разрешить резерв в параметрах, YouTube выбирается только при отсутствии или ошибке разрешения HLS КиноПоиска. При выключенном параметре YouTube исключается и из метаданных трейлеров, и из серверного playback-контракта.

Плагин отдаёт официальный YouTube URL клиенту и объявляет в capabilities `YoutubePlaybackRoute=client-direct`, `YoutubeServerProxy=false`. Поэтому HTTP-прокси, указанный только серверу Jellyfin, не меняет маршрут трафика Android TV: видео запрашивает само клиентское устройство. Без изменения клиента направить этот трафик через домашний сервер можно на сетевом уровне — политикой маршрутизации для IP телевизора или отдельного VLAN на OPNsense/домашнем шлюзе. Плагин не извлекает, не скачивает, не кэширует и не ретранслирует медиапотоки YouTube.

## Безопасность и границы

- middleware выполняет подготовку только после проверки токена штатным `IAuthorizationContext` Jellyfin;
- принимается только HTTPS-виджет `widgets.kinopoisk.ru`, а конечный HLS дополнительно проверяется существующим resolver;
- исходные медиафайлы, NFO и каталоги фильмов не изменяются;
- кэш хранится в каталоге данных плагина `cache/trailers`;
- подписанные HLS-адреса и API-токен не записываются в отчёты;
- YouTube остаётся обычным резервом API воспроизведения и не загружается в локальный кэш этой версии.

## Административные маршруты

Маршруты диагностики сохранены и требуют административной политики Jellyfin:

- `GET /KinopoiskPlayback/native-bridge/{kinopoiskId}?movieId={JellyfinMovieId}`;
- `POST /KinopoiskPlayback/native-bridge/{kinopoiskId}?movieId={JellyfinMovieId}`;
- `DELETE /KinopoiskPlayback/native-bridge/{kinopoiskId}?movieId={JellyfinMovieId}`.

Статистика и пользовательское состояние доступны отдельно:

- `GET /KinopoiskPlayback/cache/statistics` — только администратору;
- `GET /KinopoiskPlayback/cache/status/{kinopoiskId}` — авторизованному пользователю, без локальных путей и внешних URL.

Они принимают любой положительный Kinopoisk ID. Явный `movieId` устраняет неоднозначность, если фильм присутствует в нескольких библиотеках. Ручной `POST` синхронно проверяет HLS, создаёт MP4 и регистрирует LocalTrailer; повседневная работа не требует ручного вызова.
