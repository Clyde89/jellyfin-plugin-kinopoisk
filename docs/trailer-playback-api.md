# Серверный API трейлеров КиноПоиска

API предназначен для Jellyfin Web и будущего нативного Android TV-клиента. Все маршруты требуют обычную авторизацию Jellyfin и не раскрывают API-токен поставщика метаданных.

## Возможности

`GET /KinopoiskPlayback/capabilities`

Возвращает версию контракта, порядок источников и поддерживаемые способы воспроизведения. Для схемы `1` сервер выбирает КиноПоиск первым, а YouTube использует только как резервный источник.

В версии `10.11.0.10` ответ также содержит `nativeTrailerBridge`: автоматическую регистрацию штатного `LocalTrailer`, ленивую фоновую подготовку локального MP4, область клиентов, режим заполнения и допустимое ожидание первого запуска. Механизм работает для всех положительных Kinopoisk ID с доступным виджетом КиноПоиска. Полный контракт описан в [native-trailer-bridge.md](native-trailer-bridge.md).

## Выбор трейлера

`GET /KinopoiskPlayback/trailers/{kinopoiskId}`

Ответ содержит выбранный сервером источник в `selected` и резервные источники в `fallbacks`.

- `provider=kinopoisk`, `playbackKind=hls`: `url` содержит краткоживущий HLS-манифест, а `requestHeaders` — заголовки, которые клиент должен передавать Media3/ExoPlayer для манифеста и сегментов.
- `provider=youtube`, `playbackKind=youtube`: `videoId` предназначен для YouTube-плеера, `url` содержит каноническую внешнюю ссылку.
- `404`: API КиноПоиска не вернул ни разрешаемого виджета, ни поддерживаемой ссылки YouTube.
- `502`: недоступен сам upstream API трейлеров. Ошибка отдельного виджета не приводит к `502`, если доступен YouTube-fallback.

HLS-адрес не следует сохранять постоянно: сервер кэширует успешное разрешение на 10 минут, а неудачное — на одну минуту. Текущая версия отдаёт прямой HLS (`directHls=true`, `hlsProxy=false`). Прокси плейлистов и сегментов следует включать отдельным совместимым расширением схемы только если runtime-проверка подтвердит обязательные cookies, сетевую недоступность CDN с телевизора или CORS-ограничения веб-клиента.

## Проверка в реальном окружении

13 августа 2026 года серверная цепочка разрешения проверена на `media-core` с фильмом КиноПоиска `430`:

- Kinopoisk Unofficial API вернул пять источников `KINOPOISK_WIDGET`;
- страница первого виджета успешно разрешена в HLS на доверенном домене `strm.yandex.ru`;
- master playlist содержит 55 вариантов и объявляет H.264/AAC (`mp4a.40.2`);
- лучший вариант 640×480 разрешён в конечный VOD media playlist из 28 сегментов;
- `ffprobe` из контейнера Jellyfin подтвердил H.264-видео и двухканальное AAC-аудио stereo;
- запросы выполнены через сетевой маршрут Jellyfin с обязательными `Referer` и `Origin`.

Полные подписанные URL, API-токен и содержимое query-параметров в отчёт не включались. Проверка подтверждает прямой HLS для текущего источника; необходимость серверного прокси будет оцениваться отдельно на Android TV и других клиентских сетях.

Точный кандидат затем транзакционно установлен на Jellyfin `10.11.11`. Маршрут возможностей без авторизации вернул HTTP 401. После создания временной пользовательской сессии подтверждены схема `1`, приоритет `kinopoisk → youtube`, прямой HLS и отключённый HLS-прокси. Маршрут `KinopoiskPlayback/trailers/430` выбрал `kinopoisk/hls`, а возвращённый манифест ответил HTTP 200 и содержал `#EXTM3U`. Временная сессия Jellyfin после проверки завершена.

## Ограничения безопасности

- Страница виджета принимается только с `https://widgets.kinopoisk.ru`.
- HLS разрешён только на доверенных доменах КиноПоиска и Яндекса.
- Автоматические redirect-ы отключены; каждый переход проверяется сервером.
- Ответ страницы ограничен 2 МиБ, проверка HLS — 64 КиБ.
- URL не записываются в логи и используются в ключах кэша только после SHA-256.
