# Проверенная установка кандидата через systemd

Была подготовлена редакция `r3` операционного пакета кандидата `12.1.0.3` для Jellyfin 12.1. Исправление установщика из `r2` было сохранено. Бинарные файлы кандидата из коммита `1398da5fa4abd15351649162c48271c56140e577` были сохранены без изменений.

## Исправление автономного обновления

В сценарии `offline_native.py` было исключено ожидание `DateLastRefreshed`, которого не было в публичном `BaseItemDto` Jellyfin. Обновление было подтверждено чтением нового уникального описания из NFO отдельного тестового фильма. Для замены прежнего описания был выбран `FullRefresh` с `replaceAllMetadata=true` только для сохранённого ID тестового фильма. Ответ о постановке обновления в очередь не был принят за завершённую проверку; ожидание неизменённого описания завершилось ошибкой. Проверка нового описания была повторена после перезапуска.

Было проверено продолжение сохранённого теста `r2` без пересоздания библиотеки и MP4-кэша. Для такого продолжения были подготовлены распаковка `r3` в отдельный каталог и команда `offline_native.py run --restart`; переустановка DLL и удаление теста не потребовались.

```sh
python3 /tmp/kinopoisk-12.1.0.3-systemd-r3/offline_native.py run --restart
```

Были выполнены 56 проверок служебных сценариев, включая отсутствие внутренней даты в API, асинхронное обновление, непрочитанный NFO, сохранение ID и обнаружение потери нового описания после перезапуска.

## Исправленный сбой

При обновлении прежние DLL и `meta.json` были удалены, но каталоги пакетов оставались в дереве плагинов. Jellyfin восстанавливал манифест пустого каталога по его имени, присваивал другой GUID и сортировал пакеты сначала по имени и GUID, затем по версии. При последующей очистке по имени каталог нового кандидата удалялся, а установщик сообщал о несовпадении DLL.

Сценарий с пустым `КиноПоиск_12.1.0.2` и кандидатом `КиноПоиск_12.1.0.3` был воспроизведён на исходных методах `LoadManifest`, `DiscoverPlugins`, `TryGetPluginDlls`, `ChangePluginState` и `SaveManifest` Jellyfin 12.1. После исправления тот же обработчик сохранил обе DLL кандидата.

Прежние пакеты и подтверждённые оставшиеся каталоги были перенесены целиком в `retired-plugin-folders` внутри резервной копии до запуска службы. Постоянный каталог `Jellyfin.Plugin.Kinopoisk`, его кэши и XML-настройки были сохранены. В постоянном каталоге были удалены только прежние DLL, PDB, `deps.json` и манифест пакета.

Проверка контрольных сумм была выполнена перед запуском и после готовности Jellyfin. При расхождении были добавлены имя файла, признак наличия и ожидаемая/фактическая SHA-256. Ошибка сохранения диагностики не помешала автоматическому откату.

## Состав операционного пакета

Исходные служебные скрипты и тесты были сохранены в этом каталоге. `plugin.zip` был получен из указанного в `manifest.json` артефакта CI; DLL и архив не были добавлены в Git. Контрольные суммы DLL, архива и встроенного WebClient были зафиксированы в манифесте. В `SHA256SUMS` готового операционного пакета были зафиксированы контрольные суммы всех его файлов.

Проверки служебных скриптов были выполнены командой:

```sh
python3 -m unittest discover -s tools/systemd -p 'test_*.py' -v
```

## Проверка на целевом сервере

Архив `kinopoisk-12.1.0.3-systemd-r2.zip` был подготовлен для передачи в LXC 101:

```sh
pct push 101 /tmp/kinopoisk-12.1.0.3-systemd-r2.zip /tmp/kinopoisk-12.1.0.3-systemd-r2.zip &&
pct exec 101 -- python3 -m zipfile -e /tmp/kinopoisk-12.1.0.3-systemd-r2.zip /tmp/kinopoisk-12.1.0.3-systemd-r2 &&
pct exec 101 -- python3 /tmp/kinopoisk-12.1.0.3-systemd-r2/deploy.py install
```

Проверка установленного пакета была выделена в отдельную команду:

```sh
python3 /tmp/kinopoisk-12.1.0.3-systemd-r2/deploy.py check
```

Для просмотра текущих пакетов и сохранённого состояния после отката был добавлен режим без записи и перезапуска:

```sh
python3 /tmp/kinopoisk-12.1.0.3-systemd-r2/deploy.py diagnose --backup <каталог-резервной-копии>
```

Этот режим не потребовал корректного состава установленного пакета и сохранил сведения об отсутствующих DLL и повреждённом `meta.json`.

## Границы подтверждения

Были проверены обработка каталогов исходными методами Jellyfin, контрольные суммы, сохранность XML и кэшей, архивирование полных прежних пакетов и восстановление при ошибках. Установка редакции `r2` на целевом сервере была подтверждена: запуск, WebClient и Bootstrap прошли проверку; файл `index.html` на диске не изменился. Автономный сценарий остановился на неподдерживаемом поле даты обновления. Исправленный сценарий `r3` на целевом сервере ещё не был подтверждён. `functional_acceptance=PENDING` был сохранён; полная приёмка внешнего API и клиентского воспроизведения не была завершена. PR остался черновиком.
